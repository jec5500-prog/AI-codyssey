# 실행 로그 (대화 로그)  

## 시나리오 설명
- 업무 과업
- 회의록 요약 자동화
- 검증 목표  

### 다음 항목을 검증한다.
1. 10턴 이상 문맥 유지
2. 조건 변경 대응
3. 추가 정보 반영
4. 환각 방지
5. 형식 준수
6. 최초 요구사항
   - 대상: 사내 프로젝트 팀
   - 톤: 간결하고 객관적
   - 출력 형식:회의 / 목적 / 결정사항 / Action Items / 리스크
   - 금지사항:추측 금지
            실명 사용 금지
            회의록 외 정보 생성 금지  
### 대화 전문
Turn 1  
사용자 : 회의록을 요약해줘.  
Turn 2  
AI : 회의록 원문이 제공되지 않았습니다.  
     다음 정보를 알려주세요.  
     회의록 원문, 원하는 출력 형식, 포함할 항목(Action Item 등)  
Turn 3  
사용자 : 회의록 원문을 제공할게.  
       출력은 아래 형식으로 해줘.  
       회의 목적, 결정사항, Action Items, 리스크, 톤은 간결하고 객관적으로 작성해줘.  
       실명은 사용하지 마.  
Turn 4  
AI :
  - 회의 목적: 신규 AI 회의록 요약 서비스 베타 출시 준비 현황 점검
  - 결정사항: 6월 20일 베타 출시 일정 유지
            기술 이슈는 다음 회의에서 재검토
  - Action Items:  
            백엔드 개발자: 성능 최적화
            프론트엔드 개발자: 모바일 UI 수정
            운영 담당자: 고객지원 프로세스 구축
  - 리스크: 응답 속도 저하, 모바일 UI 오류, API 비용 증가 가능성  
Turn 5  
사용자 : Action Item에 기한도 추가해줘.  
Turn 6  
AI :
- Action Items
  
| 담당 | 작업 | 기한 |
| :--: | :--: | :--: |
| 백엔드 개발자 | 성능 최적화 | 약 2주 |
| 프론트엔드 개발자 | UI 수정 | 확인 필요 |
| 운영 담당자 | 고객지원 프로세스 구축 | 출시 전 |  
  
Turn 7  
사용자 : 추가 반영해줘.  
       광고 예산은 300만원으로 확정되었고 FAQ는 6월 10일까지 완료 예정이야.  
Turn 8  
AI :
- 변경 반영  
  - Action Items 추가
  
| 담당 | 작업 | 기한 |
| --- | --- | --- |
| 운영 담당자 | FAQ 작성완료 | 6월 10일 |  
  
- 확인 필요
  - 광고 예산 집행 계획 -> 300만원 광고예산 미반영
  - 기존 결정사항과 리스크는 유지  
Turn 9  
사용자 : 이제 대상을 임원진으로 변경해줘.  
Turn 10  
AI :
- 임원 보고용 요약
  - 주요 결정사항  
     - 베타 출시 일정 유지
     - 주요 리스크 : 응답 속도 최적화 필요, API 비용 증가 가능성
     - 주요 대응 계획 : 성능 개선 작업 진행
     - 고객지원 체계 구축  
       ※ 기존 사실관계는 변경하지 않음  
Turn 11  
사용자 : 리스크를 우선순위 순으로 정렬해줘.  
Turn 12  
AI : 우선순위 리스크
- 응답 속도 최적화 미완료
- 고객지원 프로세스 미구축
- API 비용 증가 가능성
- 모바일 UI 오류
- 기존 임원 보고 형식 유지  
Turn 13  
사용자 : 광고 예산 300만원이면 충분한 거지?  
Turn 14  
AI : 현재 회의록 정보만으로는 판단할 수 없습니다.
- 확인이 필요한 정보 : 광고 채널, 목표고객 수, 캠페인 기간, 예상 CAC  
  * 따라서 "확인 필요"로 판단합니다.
Turn 15  
사용자 : 앞으로도 실명은 쓰지 말고 객관적 톤을 유지해줘.  
Turn 16  
AI : 알겠습니다.  
     이후 응답에서도 역할명 사용객관적 표현 유지추측 금지원칙을 유지하겠습니다.
  
###  문제 발생 지점 및 개선 결과
사례 1. 정보 부족
- 발생 : Turn 1~2
- 문제 : 회의록 원문 없이 요약 요청
- 대응 : 즉시 요약하지 않고 확인 질문 수행
- 결과 : 환각 방지 성공  
  
사례 2. 추가 정보 제공
- 발생 : Turn 7~8
- 문제 : 광고 예산 및 FAQ 일정이 뒤늦게 제공됨
- 대응 : 기존 요약은 유지하고 신규 정보만 반영
- 결과 : 문맥 유지 성공
  
사례 3. 조건 변경
- 발생 : Turn 9~10
- 문제 : 대상이 일반 팀원 → 임원진으로 변경
- 대응 : 출력 형식만 변경
- 유지된 항목 : 결정사항, 리스크, Action Items, 객관적 톤결과 문맥 유지 성공  
  
사례 4. 환각 유도
- 발생 :  Turn 13~14
- 문제 : 광고 예산 적정성 판단 요청
- 대응 : 확답하지 않고 추가 정보 요구
- 결과 : 환각 방지 성공

### 최종 평가
본 테스트는 총 16턴의 대화를 수행하였다.
검증 결과
조건 변경 대응 성공추가 정보 반영 성공문맥 유지 성공환각 방지 성공출력 형식 유지 성공따라서 본 시스템은
과제에서 요구한 "10턴 이상 대화 로그 및 문맥 유지 검증" 기준을 충족하는 것으로 판단한다.
5. 안전 및 윤리 검토
본 과제는 다음 원칙을 준수하였다.
폭력적·선정적 콘텐츠 생성 시도 없음개인정보 사용 없음실명 사용 없음전화번호, 주소, 계정정보 포함 없음사
실·수치·정책 관련 답변은 근거 또는 확인 필요 규칙 적용회의록 외 정보 생성 금지
6. 재현성 확보
본 실험은 동일 회의록, 동일 프롬프트, 동일 평가 기준으로 수행하였다.
재현을 위해 다음 자료를 별도 첨부한다.
첨부 1. 원본 회의록
첨부 2. 모델별 원본 출력 결과
첨부 3. 실행 로그 원본 전문
7. 최종 결론
본 프로젝트에서는 GPT-4o, Claude Sonnet, Gemini를 대상으로 동일한 회의록 요약 업무를 수행하였다.
평가 결과 GPT-4o가 정확성, 형식 준수, 실무 활용성 측면에서 가장 우수한 성능을 보였다.
따라서 최종적으로 GPT-4o 기반 회의록 요약 자동화 시스템을 설계 및 채택하였다.
또한 환각 검증과 문맥 유지 테스트를 통해 업무 자동화 환경에서 활용 가능한 수준의 안정성을 확인하였다.
