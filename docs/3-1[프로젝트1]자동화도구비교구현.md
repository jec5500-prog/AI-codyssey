# 1. 프로젝트 개요

본 프로젝트는 동일한 자동화 업무를 **Make**와 **n8n** 두 가지 자동화 플랫폼으로 각각 구현하고 비교 분석하는 것을 목표로 한다.

자동화 대상은 RSS 뉴스 피드에서 새로운 부동산 뉴스를 수집한 뒤,

- Notion Database 저장
- Discord 알림 전송

까지 자동 수행하는 워크플로우이다.

두 플랫폼 모두 동일한 흐름으로 구현하여 UI, 사용성, 확장성 등을 비교하였다.

# 2. 프로젝트 목표

본 프로젝트의 목표는 다음과 같다.

- 동일한 자동화를 서로 다른 플랫폼에서 구현

# 4. 자동화 대상 업무

## 자동화 업무

부동산 관련 RSS 뉴스가 새롭게 등록되면 자동으로

- Notion 데이터베이스 저장
- Discord 채널 알림

을 수행한다.

---

## 자동화 흐름

```
RSS Feed

↓

새 뉴스 감지 (Trigger)

↓

조건 검사 (Filter)

↓

Notion Database 저장

↓

Discord 메시지 전송
```

# 9. 각 도구의 장단점

## Make

### 장점

- UI가 매우 직관적이다.
- 초보자도 빠르게 구현 가능하다.
- 다양한 SaaS 연동을 제공한다.

### 단점

- 무료 플랜 제한이 있다.
- 복잡한 로직 구현이 어렵다.

---

## n8n

### 장점

- 자유도가 매우 높다.
- JavaScript 코드 사용 가능
- API 연동이 뛰어나다.
- 자가 호스팅 가능

### 단점

- 초보자에게 다소 어렵다.
- 초기 설정이 Make보다 복잡하다.

---

# 10. 어떤 상황에서 적합한가

## Make가 적합한 경우

- 자동화를 처음 시작하는 사용자
- 빠르게 Workflow를 구축해야 하는 경우
- SaaS 중심 업무

---

## n8n이 적합한 경우

- 복잡한 자동화가 필요한 경우
- API 중심 프로젝트
- 장기적인 자동화 운영
- 개발자 중심 프로젝트

본 프로젝트에서는 RSS Feed에서 새로운 뉴스가 등록되는 것이 Trigger이다.

---

## Action

본 프로젝트에서는

- Notion 저장
- Discord 메시지 전송

이 Action이다.

---

## Filter

조건을 만족하는 데이터만 다음 단계를 실행하도록 하는 기능이다.

# 13. 문제 해결 과정

## Discord Bot 연결 문제

초기에는 Bot 초대 URL이 정상적으로 동작하지 않았다.

### 원인

OAuth2 URL의 Client ID가 잘못 설정되어 있었다.

### 해결

정확한 Client ID를 사용하여 OAuth2 URL을 생성하고 Bot을 서버에 초대하였다.

---

## Discord Token 문제

Bot Token을 초기화한 뒤 기존 Credential이 동작하지 않았다.

### 해결

새로운 Token을 발급받아 n8n Credential을 다시 등록하였다.

---

## Discord 메시지 변수 출력 문제

초기에는

```
{{ $('RSS Feed Trigger').item.json.title }}
```

문자 그대로 출력되었다.

### 원인

Expression 모드가 아닌 일반 문자열로 입력되어 있었다.

### 해결

Expression 모드로 변경하여 정상 출력하였다.
